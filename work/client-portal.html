Streamlined onboarding via client portal

Enabling prospects to securely submit bank statements, providing the data needed for personalised financial health reports.

01

Overview

Background

Collecting bank statements for personalised financial health check reports lacked a standard process, causing delays and confusion for clients and internal teams.

Key problems

Client confusionProspects don’t know how many statements to send or forget to submit them.
Disorganised submissionStatements arrive via multiple channels, making it hard to track completeness.
Internal uncertaintyAnalysts and data input teams cannot tell when data is ready, delaying reports.

Solution

Effortless submissionBuilt a Client Portal for secure and easy statement uploads.
Real-time trackingStandardised workflow lets client service and data input teams monitor uploads instantly.
Statement data scoreDesigned indicates when client statements are ready for reporting.

Outcomes

Time reduced 38.5%Average collection time dropped from 6.5 weeks → 4 weeks.
Positive feedback 94%46 out of 49 clients gave positive feedback (Mar–Sep 2021)
7,932 statements collectedThrough the Client Portal.
02

Discover

Stakeholder interviews

Conducted stakeholder interviews to uncover unclear submission processes, missing statements, and delays in report generation.

Prospects didn’t know how many statements to send or forgot to send them.

Statements were submitted via multiple emails or random app chats, leaving client service unsure of completeness.

Analysts couldn’t determine when they could start preparing reports.

No standardised process for collecting and verifying statements.

03

Define

User stories

Clients: Submit statements securely, effortlessly, and know exactly what’s needed.

Client Service: Track client progress and see which statements are received.

Data Input Team: Know which statements to upload daily and when profiles are complete.

Analysts: Access verified statements to generate reports efficiently.

Objective

1. Effortless & Secure Submission

Prospects can submit bank statements easily and securely via the Client Portal.

2. Transparent Workflow

Client service and data input teams can track uploads in real time and start processing immediately.

3. Ready-to-Use Data

Analysts know when all statements are complete, enabling timely generation of financial health check reports.

The key problem

Incomplete or random client submissions stall the workflow and delay reporting.

Clients forget or send statements inconsistently, leaving client service unsure when submissions are complete. Without complete statements, the rest of the process cannot move forward.

04

Design & Iterate

Brainstorming with stakeholders

We try to turn those users’ need into how might we questions and brainstorm with advisors, analysts and client service team together.

Decision: Build a Dedicated Client Portal. Instead of using shared drives or third-party tools, we chose to build our own storage app because:

Extensible Functionality – We can add features tailored to client onboarding, document validation, and workflow tracking.

Full Control & Security – Sensitive client data remains fully under our control, ensuring compliance and reducing risk.

Seamless Integration – The portal integrates directly with internal systems, enabling real-time updates for analysts and client service teams.

New user journey

Mapped the user journey for statement uploads, walking stakeholders through it to uncover missing steps and potential issues.

Phase one goal

Enable prospects to send their statements securely and effortlessly

Login UX benchmarking

Researched login security methods used by banks and fintechs, including:

Personal info + OTP

Mobile number + passcode + app authentication

Personal info + QR code

Evaluated pros and cons and, after discussing with PM and developers, chose mobile number + OTP because:

Consistent with our existing mobile login experience

Leverages existing mechanism, saving resources

Most familiar and comfortable for elder clients

User flow

Key screens exploration

Prototype

Rapid prototyping enabled quick stakeholder feedback and informed final design.

Feedback & revised layouts

Key Issues Identified:

Progress Tracking Unclear – Statements arrive monthly, quarterly, or semi-yearly, making automatic sufficiency detection difficult. Progress bars for quarters needed redesign, and we explored ways to let clients know if enough statements were submitted.

UI Needs Upgrade – The client-facing web app felt less engaging; it should appear elegant, luxurious, and visually appealing.

Proposed Solution:

Designed three new layouts using “folder” imagery to indicate drag-and-drop file upload.

Added animation and instructions to clearly show clients how many statements are needed and how to submit them.

Design Comparison: Initial vs Latest

Cleaner Layout – Provider blocks redesigned as folder shapes for clarity and simplicity.

Luxury UI – Dark theme applied to enhance elegance and friendliness.

Removed Status Bars – Not feasible; simplified progress tracking.

Auto-Save Uploads – Removed SEND button to prevent data loss and reduce steps.

Improved Navigation – Added logout and profile switching options.

Future Enhancements – Client-added providers postponed due to limitations; low priority as initial provider list is usually complete.

Outcome & Learnings

Business impact

Next steps

Track Statement Uploads – Show number of uploaded statements or other indicators so client service and data input teams can start processing.

Ready-to-Run Indicator – Implement a Statement Data Score to let analysts know when client data is complete for generating health check reports.

Retrospective

The project streamlined client statement submission, improved workflow transparency for internal teams, and enhanced the UI to be more engaging. Key learnings included balancing security with usability, designing for multiple user roles, and iterating based on stakeholder feedback.
